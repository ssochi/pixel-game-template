# M00 — 探索里程碑：现状勘察

**状态**：已结案
**方式**：通读 15,274 行 TypeScript；用 Playwright 在 4 倍放大下截了 16 张实机画面
（户外 6 个地点 × 昼/夜、8 个室内、桥与河段）；查外部参考。

---

## 一、现在这个游戏是什么

一个**已经能玩完一整天循环**的种田生活模拟：

开荒 → 播种 → 浇水 → 睡觉过夜 → 收获 → 出货箱卖钱 → 杂货铺买种子，经济闭环成立。
外加钓鱼小游戏（两张鱼表、深潭、900G 的河王）、8 位有名有姓的居民（好感度 / 送礼 / 三档对白）、
四环任务链、8 种可进入的室内、昼夜光照、逐像素渲染的河流。

技术底子扎实：

- 美术**全部程序化生成**，仓库零图片。约 1 秒烘焙完成
- 调色板纪律真的在执行：`bakeSheet()` 对每帧 `quantize()`，色相偏移色阶，选择性描边
- `riverSDF()` 一份数据同时驱动水面渲染、沙岸烘焙和碰撞判定——美术和玩法不可能对不上
- 人物是参数化骨架，5 套动作 × 3 朝向 99 帧由同一段代码产出
- `npx tsc --noEmit` 干净通过

**结论：地基是好的，问题不在管线，在两个别的地方——一批具体的视觉缺陷，和一批缺失的系统。**

## 二、实机截图里看到的缺陷

按严重程度排。每条都是在 4 倍放大画面里肉眼可见的，不是代码审查的推测。

### A. 有一个村民是纯黑色人形

`src/art/character.ts:161`

```ts
villager(R.night, R.night, R.metal, R.night, { hooded: true }), // stranger
```

`R.night` 的明度档是 `[0.06, 0.11, 0.17, 0.26, 0.38]`（`palette.ts:114`）。
外套取 `night[2]`=0.17、裤子 `night[2]`=0.17、头发 `night[2]`=0.17，再加 `hooded` 把脸挡住——
**一个没有五官的纯黑剪影**。

在 04-river 的街上有两个，在教堂讲台后面站着的也是它（11-chapel）。
玩家的第一反应是"这里有个 bug"或者"这是敌人"，而不是"这是个陌生人"。
色阶纪律这一条在这里恰恰是被违反的：一个角色的外套、裤子、头发用了**同一条色阶的同一档**，
等于没有明度分离。

### B. 地毯、被褥、床是一块平色板

`src/art/interiors.ts:566` `roomRug()`：

```ts
b.fillRect(0, 0, w, h, ramp[1]);
b.fillRect(1, 1, w - 2, h - 2, ramp[2]);
b.fillRect(4, 3, w - 8, h - 6, ramp[1]);
b.fillRect(6, 4, w - 12, h - 8, ramp[3]);
b.fillRect(w/2 - 3, h/2 - 2, 6, 4, ramp[1]);
```

一张 48×34 的地毯 = 5 个同心矩形。没有织纹、没有流苏、没有磨损。
`R.purple` 那一张在木地板上读成一块**洋红色贴纸**（07-shop、09-cottage）。
床的被面用的是同一套画法，所以**玩家每天晚上要走过去按 E 睡觉的那张床，是一块洋红色矩形**。

这违反了项目自己的美术规则第 4 条与第 11 条的精神：这个尺寸上"平面 + 转折"才有体积，
而同心矩形既不是平面也不是转折，是靶环。

### C. 室内地板是通铺的水平木条

09-cottage / 07-shop：整个房间的地板是从左墙到右墙、间距完全一致的水平横线。
读成一块**甲板**而不是一间屋子的地板。`interiors.ts` 里有 `wearPath()` / `floorStain()` /
`floorPatches()` 这些做磨损的函数，但底纹本身的重复周期太规整、幅度太大，磨损盖不住它。

教堂的方砖同理：16px 一格的完美棋盘，一个缺角都没有（11-chapel）。

### D. 教堂的长椅读成搁板

11-chapel：两列长椅每一张都是"一条深色横板 + 一条浅色横板"，悬空叠在地上。
README 说"带靠背的长椅"，但从上往下看，靠背没有画出厚度和投影，
结果是**八块贴在地上的木板**。旁边的蜡烛跟人一样高——烛台 + 蜡烛的整体高度接近 30px，
和玩家身高一致，尺度错了一个量级。

### E. 水里的石头戴着一个"放大镜"

06-woods：河心的两块石头，每块外面套着一圈**闭合的白色圆环**。
`water.ts:212` 的泡沫环画成了完整的圆。真实的白水只在**迎流面**堆起来、在下游拉成 V 形尾迹，
不会绕着障碍物围一整圈。现在读成放大镜或者游泳圈。
（这条在根目录 README 的"已知残留"里已经记着，一直没修。）

### F. 玩家自己的农场是一块空草坪

01-farm-day：整个画面右半边是一个巨大的、四面围栏的**纯草地矩形**，
里面一株作物、一垄翻好的土都没有。这是玩家开局站的地方，是这个游戏的门面。

对比 02-square 左上角 NPC 的麦田：那是密密麻麻**完全一样的麦穗印章**铺满一个矩形，
边缘一刀切齐，反而更糟——读成墙纸。

围栏本身也是问题：横杆水平、立柱等距、没有任何视角，读成**一架躺倒的梯子**
（根目录 README 也记着这条）。

### G. 树林里散落着上一个项目的道具

06-woods：河对岸的草地上摆着一个**宝箱、一个药水瓶、一颗宝石、一枚金币、一堆篝火**，
外加一只史莱姆在爬。这些是这个仓库从 "Gungeon 素材测试场景" 演化过来时留下的展品。
在一个种田游戏的野外，它们不说明任何事情——玩家会去开箱子，然后发现开了没用。

同一批残留还包括：`player.ts` 里的枪与子弹系统、`agents.ts` 的史莱姆 AI、
`main.ts:708` 的"子弹打史莱姆"碰撞循环。README 自己写着"待决定去留"。

### H. 世界的密度是空的

除了小镇那几条街，大部分地图是**大片纯草地 + 零星的褐色土斑**。
草地上那些深褐色斑块尺寸很大、边缘是抖动噪点，读成污渍而不是裸土。
道路是一条宽的褐色带，两边靠抖动过渡到草地，没有明确的边沿——读成一条泥浆。
河岸的芦苇是**完全相同的一簇，等距排成一列**。

### I. HUD 的默认状态挡住了游戏

`main.ts:400` `showHelp = true`。开局左侧三分之一的画面被调试帮助面板占据。
同时左上角的任务横幅（"NOTICE: FIRST HARVEST"）和时钟胶囊在 y 轴上**贴在一起甚至重叠**。

### J. 室内房间浮在黑色虚空里

所有室内房间都比 448×252 的视口小，摄像机居中之后，左右各留一条很宽的纯黑边。
房间读成"一张浮在黑色里的卡片"，而不是"我在一栋房子里"。

## 三、缺失的系统

这些不是缺陷，是这个游戏**还没有的部分**。按缺了之后玩家最先撞到的顺序排：

| 缺什么 | 后果 |
| --- | --- |
| **存档** | 关掉标签页，一切归零。这是目前最大的单点问题——所有别的内容都因此无法积累 |
| **季节** | 一天 150 秒循环，但天永远是同一天。没有"这一季快过去了"的压力，作物没有窗口期 |
| **天气** | 下雨免浇水、雷雨、雪，是农场游戏调节节奏最便宜的手段。现在完全没有 |
| **真正的背包** | 只有 10 格快捷栏，6 件工具占掉大半。装满了会弹提示——但格子就是不够 |
| **音效 / 音乐** | 完全静音。锄地、收获、开门、下雨都没有反馈 |
| **矿洞** | 镐子现在只能敲地表的石头。没有纵深、没有稀有资源、没有工具升级的目标 |
| **制作 / 烹饪** | 木料和石料除了交任务没有出口。洒水器、箱子、料理这些"钱之外的目标"都不存在 |
| **节日** | 一年里没有任何一天和别的日子不一样 |
| **地图 / 引导** | 新玩家不知道镇子有多大、店在哪、床在哪 |

## 四、外部参考里学到的

查了 Stardew Valley 的设计分析（见文末）。有三条直接适用：

1. **系统之间要互相喂。** Stardew 之所以耐玩，不是因为系统多，而是因为
   "钓上来的鱼可以做肥料也可以当礼物；挖到的矿石造洒水器，洒水器自动浇水，
   于是农场规模能扩大"。本项目现在的系统是**并联**的：种田、钓鱼、好感、任务
   四条线彼此几乎不通电。钓的鱼只能卖和送礼；砍的木头只能交任务。
   → 蓝图里每加一个系统，都要问"它往哪两个已有系统里回流"。

2. **季节是最便宜的内容倍增器。** 换一批作物、换一批鱼、换一次地面色相、加一个节日，
   同一张地图就变成四张。对一个"美术全是代码生成"的项目来说，
   季节尤其便宜——地面色阶换一档就是换季，不需要重画任何素材。

3. **经济必须是递归的**：赚钱是为了花钱去赚更多钱。本项目的经济已经闭环了（种子便宜、
   作物贵），但缺**扩张的出口**——赚到 5000G 之后没有任何东西可买。

## 五、判断

**不做大重构。** 管线、调色板纪律、SDF 河流、参数化骨架这些是这个项目最值钱的东西，
动它们等于把优势扔掉。

要做的是两件事，按这个顺序：

1. **先把已经做出来的东西修干净**（第二节 A–J）。
   一个纯黑色的村民和一块洋红色的床，比"没有矿洞"更伤害这个游戏——
   前者让人觉得它是坏的，后者只让人觉得它小。
2. **然后按"存档 → 季节天气 → 背包 → 纵深系统"的顺序补系统**。
   存档必须排第一：在它落地之前，后面每一个系统做出来的进度都是留不住的。

蓝图见 `docs/ROADMAP.md`。
